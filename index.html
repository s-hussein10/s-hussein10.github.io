// CASE STUDY 01 — GRADUATION PROJECT
Lighting Controller with FOTA Bootloader (STM32F401CC)
STM32F401CC (ARM M4)MCAL / HAL / APP FOTA BootloaderESP32 + Node-RED SPI TFT & DMANEC IR & R2R DAC
Overview

An industrial-grade ARM Cortex-M4 (STM32F401CCU6) bare-metal embedded system built completely from scratch using a strict MCAL / HAL / APP layered architecture. It eliminates wired programmers (ST-Link/JTAG) by implementing a Custom FOTA Bootloader that streams Intel .hex firmware wirelessly from a Node-RED Control Center through an ESP32 Wi-Fi bridge, erases & programs internal Flash sectors in real time, and cleanly jumps to the updated Smart Room Automation Application (multi-speed fan, lighting, TFT UI, 8×8 LED Matrix, 7-Segment, NEC IR remote, and 8-bit R2R DAC audio feedback).

System Architecture & Flash Memory Layout
Technical Architecture
Target MCUSTM32F401CCU6 Black Pill (ARM Cortex-M4 @ 84 MHz, 256 KB Flash)
Software LayersBare-Metal C — MCAL (RCC, GPIO, NVIC, EXTI, STK, USART, SPI, FMI, DMA), HAL, APP
Flash PartitioningSector 0 (0x08000000, 16 KB) Bootloader · Sectors 1–5 (0x08004000, 240 KB) User App
FOTA ProtocolESP32 streams Intel .hex records (Types 00, 04, 01) over USART1 with "ok" ACK handshake
Context SwitchRelocates SCB->VTOR = 0x08004000, loads MSP & jumps to App Reset_Handler
Cloud & Control UIESP32 Wi-Fi Bridge + Node-RED Dashboard (/fota/status, /cmd, /start, /progress)
Peripherals & AudioSPI1 TFT (ILI9341/ST7735), TSOP1738 NEC IR, 74HC595 8×8 Matrix, 7-Seg, 8-bit R2R DAC @ 8 kHz
Key Challenge

Problem: Flashing new firmware wirelessly over UART risks corrupting internal Flash if packets arrive faster than Flash sector erase/write operations, or crashing on jump if the vector table and stack pointer are not cleanly relocated.

Solution: Implemented a deterministic 15-second SysTick boot window, sector-by-sector FMI Flash erase/write on the first valid Intel HEX record, a strict line-by-line "ok" UART flow-control handshake with the ESP32 bridge, and a clean context switch relocating SCB->VTOR, loading the application's MSP from 0x08004000, and jumping to Reset_Handler at 0x08004004.

3-Axis PCB CNC Milling & Plotting System + CNC Plotter Studio
GRBL 1.1h / ATmega328P3-Axis CNC / NEMA 17 Z-Probe & Bilinear LevelingWeb Serial API CAM / G-CodeVanilla JS (EN/AR)
Overview

A complete end-to-end mechatronic rapid PCB prototyping system replacing hazardous chemical etching and fragmented desktop CAM pipelines. Pairs a rigid 3018-class 3-Axis Cartesian PCB CNC (Arduino Uno / ATmega328P running GRBL 1.1h, CNC Shield V3, 3× A4988 & NEMA 17 steppers, T8 lead screws @ 400 steps/mm = 0.0025 mm/step) with a Conductive Z-Probe & Bilinear Auto-Leveling subsystem (<0.05 mm compensation) and CNC Plotter Studio — a zero-dependency browser CAM & controller communicating directly over USB via the Web Serial API.

System Architecture
Technical Architecture
Embedded ControllerArduino Uno (ATmega328P @ 16 MHz) running GRBL 1.1h real-time firmware (Timer1 30 kHz Bresenham ISR)
Mechanics & Drive3018-class aluminum Cartesian gantry, LM8UU bearings, T8 lead screws, 3× NEMA 17 + A4988/DRV8825
Axis Calibration200 × 16 / 8 = 400 steps/mm (0.0025 mm/step) + automated Calibration Wizard writing GRBL EEPROM ($100–$102)
Web ControllerCNC Plotter Studio — zero-dependency Vanilla JS, HTML5 Canvas, Web Serial API, 128B RX Character-Counting streamer
CAM & GeometrySVG CTM flattener, Marching Squares contours, Zhang-Suen centerline thinning, Dark Hatching, RDP & TSP path optimizer
PCB Auto-LevelingConductive Z-Probe (Pin A5 + GND), G38.2 N×M grid heatmap & bilinear Z-interpolation (segments ≤ 2 mm)
UI & DiagnosticsFull EN / AR (RTL) localization, live 150 ms DRO & Pn:P probe monitor, 37 GRBL errors & 9 alarms, E-STOP
Key Challenge

Problem: Copper-clad FR4 boards have a copper layer of only 35 µm (0.035 mm), while natural board warp is typically 0.1–0.3 mm. Without surface compensation, one side of the PCB is milled far too deep while the opposite side isn't isolated at all.

Solution: Engineered a Conductive Z-Probe (GND clip on the engraving bit, A5/SCL clip on the copper surface) with live Pn:P continuity diagnostics. CNC Plotter Studio runs an automated G38.2 N×M grid scan, plots a board flatness heatmap (Min / Max / Δ mm), subdivides cutting moves to ≤ 2 mm, and applies bilinear Z-interpolation across every coordinate — achieving sub-0.05 mm isolation milling accuracy across warped boards.

// CASE STUDY 03
PIC-Based Intelligent Temperature Management
C / MikroC PROPIC16F877A LM35ADCPWM
Overview

An automated temperature monitoring and control system built around the PIC16F877A microcontroller. It integrates an analog LM35 sensor with a digital interface and actuators to maintain safe thermal parameters through a tiered response protocol.

System Architecture
Technical Architecture
MicrocontrollerPIC16F877A (8-bit, 20MHz)
Temperature SensorLM35 — Analog, 10mV/°C output
Signal ProcessingADC conversion → Temp°C = V(mv) / 10
Actuator 1DC Motor (Cooling Fan) — PWM speed control
Actuator 2Tri-color LED — Green / Yellow / Red alerts
SoftwareBare-metal C, MikroC PRO compiler
Safety Protocol3-tier: Safe (<30°C) / Warning (30–45°C) / Critical (>45°C)
Key Challenge

Problem: Raw ADC readings from the LM35 were noisy, causing the fan to rapidly switch on and off (chattering) near threshold temperatures, which risks motor damage and poor UX.

Solution: Implemented a hysteresis band of ±2°C around each threshold. The system only transitions between states when the temperature crosses the threshold by this margin, eliminating chattering entirely and stabilizing the control loop.

CATmega32 ×2 SPIUARTPWM
Overview

A decentralized home automation system using a Master/Slave ATmega32 configuration. The Master handles security authentication and fire detection, while the Slave manages climate and lighting via SPI inter-node communication. User interaction is via UART.

System Architecture
Technical Architecture
MicrocontrollersDual ATmega32 (AVR) — Master/Slave topology
Inter-node Comm.SPI — Master dispatches commands to Slave
User InterfaceUART — Serial login and command input
Security LayerCredential-based login, 3-attempt lockout
Door ControlPWM-driven Servo motor
Signal QualityMoving Average Filter on analog sensor readings
SafetyFire Alarm with automatic ventilation trigger
Key Challenge

Problem: The Master node was becoming overloaded handling both security events (login, fire alarm) and environmental control simultaneously, causing delayed response to critical security triggers.

Solution: Offloaded all lighting and climate logic to the Slave node via SPI, freeing the Master to dedicate its cycles entirely to time-critical security events. This distributed architecture ensures the Master always responds to intrusion or fire events with zero delay regardless of environmental workload.

A professional-grade IoT ecosystem that cleanly separates mission-critical security from environmental automation. The ESP32 handles biometrics, RFID, cloud sync, and the Blynk mobile dashboard, while the Arduino Uno manages all hardware I/O, bridged via a JSON-based UART protocol with hardware voltage divider for 5V→3.3V signal integrity.

System Architecture
Technical Architecture
IoT GatewayESP32 — WiFi, Blynk cloud integration
SecurityR307 Fingerprint + RFID RC522 + Keypad (3-factor)
IPC ProtocolJSON-based UART between ESP32 and Arduino Uno

Key Challenge

Problem: Direct UART connection between the 3.3V ESP32 and 5V Arduino caused signal integrity issues and risked permanent damage to the ESP32's GPIO pins.

Solution: Designed a resistive voltage divider circuit on the Arduino TX line to safely step down the 5V signal to 3.3V before feeding it to the ESP32 RX pin. Combined with a JSON-structured protocol over UART, this created a robust and electrically-safe inter-processor communication bridge.

// CASE STUDY 06
Automated Storage & Retrieval System (ASRS)
C++Arduino Mega 2560 Stepper MotorPneumaticsUltrasonic
Overview

An industrial-grade 3×3 warehouse automation prototype. The system manages item storage and retrieval using coordinate-based motion control across three axes — X (stepper), Y (pneumatic lift), Z (pneumatic pusher) — with a 9-node ultrasonic matrix for real-time occupancy tracking.

System Architecture
Technical Architecture
Control HubArduino Mega 2560
X-Axis MotionStepper Motor — Trapezoidal acceleration profile
Y-Axis MotionPneumatic Lift — Vertical item elevation
Z-Axis MotionPneumatic Pusher — Item ejection into slot
Occupancy Sensing9-node Ultrasonic matrix (3×3 grid coverage)
End-Stop DetectionIR limit switches on all axes
Autonomous ModeAuto-Scan: algorithmically finds free slot & stores item
Key Challenge

Problem: Moving a loaded carriage on the X-axis with a constant velocity stepper profile caused mechanical vibration and occasional step-loss under load, making positioning unreliable for precise slot alignment.

Solution: Implemented a trapezoidal motion profile — the stepper accelerates gradually from rest, cruises at target speed, then decelerates before stopping. This eliminated inertial shock, prevented step-loss, and achieved reliable ±1mm positioning accuracy across all 3 columns of the storage grid.
